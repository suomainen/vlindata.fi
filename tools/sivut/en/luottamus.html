Handling municipal data

When I carry out a property tax audit or GIS work for a municipality, the municipality is the controller of the personal data and VLiNdATA Oy is the processor. I process the data only on the municipality's instructions and only for the assignment.

Typical data includes the municipality's building register and property tax list, which contain data on owners and holders of properties and buildings, and answers to owner enquiries. I also use open data, such as building data from the Ryhti system and the National Land Survey's property boundaries and topographic database.

  • Transfer: data is received and delivered in the municipality's own Microsoft Teams environment or another jointly agreed project platform. It is not sent by email.
  • Storage: on an encrypted work computer and in Microsoft 365. Data is not copied to USB sticks or personal cloud services. Personal data is not transferred outside the EEA.
  • Personal identity codes: processed only if included in the register extracts provided by the municipality, and never included in the results.
  • Owner enquiries: I prepare the mailing list and letters with map attachments and receive the answers to the online form. The answers are delivered to the municipality or entered into its system as agreed.
  • When the work ends: the municipality's data and intermediate results are returned or deleted once the municipality has approved the result. Deletion is confirmed on request.

Security practices

  • Devices: the work computer's disk is encrypted, the operating system and software are updated regularly and malware protection is in use.
  • Accounts: every service has its own strong password in a password manager, with two-step authentication wherever the service supports it.
  • Access: everyone has their own accounts. Municipal systems are accessed only with credentials provided by the municipality and according to its instructions.
  • Backups: work files are backed up to Microsoft 365. The municipality's own systems remain within its own backups.
  • Open tools: GIS work uses QGIS and other open-source software, whose updates I follow.

GIS preparedness

The local backup system is installed in the municipality's own environment. Data is fetched from interfaces chosen by the municipality and stored on the municipality's own servers or computers; it does not pass through VLiNdATA.

  • The solution is based on open-source software (GDAL, MapLibre, QGIS). The code can be inspected by the municipality.
  • The system needs no external cloud service. Maintenance access to the municipality's environment is controlled by the municipality and agreed separately.
  • A description of the solution is available to support the municipality's continuity planning and NIS2 and ISO 22301 assessments.

Website

  • The website is static: no database, no sign-in and no stored form data. The contact form opens the message in the visitor's own email app.
  • Traffic is encrypted (HTTPS), and a content security policy allows only the site's own files and analytics.
  • Analytics starts only with the visitor's consent. Cookies
  • Third-party files used on the site are checked against known vulnerabilities.

Security incidents and reports

If a personal data breach affects the municipality's data, I will notify the municipality without undue delay and help investigate what happened, so that the municipality can make its own notifications.

If you notice a security issue in VLiNdATA's services or on this website, please email virpi@vlindata.fi. Tell me what you found and where. Please do not publish details before the issue has been fixed.

Documents on request
